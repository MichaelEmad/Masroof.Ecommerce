# ABP E-Commerce Solution Implementation

This document describes the complete e-commerce solution built using ABP Framework (.NET 9, EF Core, ABP Angular UI).

## Architecture Overview

The solution follows ABP's clean architecture with Domain-Driven Design (DDD) principles:

- **Domain Layer**: Core business logic and entities
- **Application Layer**: Application services and DTOs
- **EntityFrameworkCore Layer**: Database context and configurations
- **HttpApi Layer**: API controllers (auto-generated by ABP)
- **Angular UI**: Front-end application

## Features Implemented

### 1. Identity & Authorization

- **Roles**:
  - `SuperAdmin`: Full access to manage categories, products, allergens, and all orders
  - `Customer`: Register, browse products, manage cart, place orders, view own orders

- **Permissions**:
  - `Ecommerce.Categories.*`: Manage categories (SuperAdmin)
  - `Ecommerce.Allergens.*`: Manage allergens (SuperAdmin)
  - `Ecommerce.Products.*`: Manage products (SuperAdmin)
  - `Ecommerce.Orders.ManageAll`: View all orders (SuperAdmin)
  - `Ecommerce.Orders`: View own orders (Customer)
  - `Ecommerce.Cart`: Manage cart (Authenticated users)

### 2. Product Catalog

#### Entities
- **Category**: Product categories with soft-delete support
- **Allergen**: Allergen information for products
- **Product**: Products with name, description, price, stock, image, category, and allergens
- **ProductAllergen**: Many-to-many relationship between products and allergens

#### Features
- Full CRUD operations for SuperAdmin
- Public product browsing with filtering and pagination
- Stock management
- Soft-delete support
- Audit logging (CreationTime, CreatorId, etc.)

### 3. Shopping Cart

#### Entity
- **CartItem**: Persistent cart items stored in database

#### Features
- Add/Update/Remove items
- Cart persists across sessions
- Stock validation when adding items
- Automatic cart clearing after checkout
- Calculate total price

### 4. Orders & Checkout

#### Entities
- **Order**: Order header with customer info and status
- **OrderItem**: Order line items with product snapshot

#### Order Statuses
- `Pending`: Order created, awaiting payment
- `Paid`: Payment confirmed
- `Cancelled`: Order cancelled

#### Workflow
1. Validate stock availability
2. Create order with items
3. Deduct stock from products
4. Clear customer's cart
5. Send confirmation email via background job
6. Simulate payment (mark as paid)
7. Send payment confirmation email

#### Features
- Stock validation before order creation
- Automatic stock deduction
- Order cancellation with stock restoration
- Email notifications using ABP Emailing + Background Jobs
- Customers can view their own orders
- SuperAdmin can view all orders

### 5. Background Jobs

#### Email Notifications
- **OrderEmailNotificationJob**: Sends order confirmation email
- **OrderPaymentConfirmationJob**: Sends payment confirmation email

## Database Schema

### Tables Created
- `AppCategories`: Product categories
- `AppAllergens`: Allergen information
- `AppProducts`: Products catalog
- `AppProductAllergens`: Product-allergen relationship
- `AppCartItems`: Shopping cart items
- `AppOrders`: Orders
- `AppOrderItems`: Order items

All tables include ABP's audit fields (CreationTime, CreatorId, LastModificationTime, etc.)

## API Endpoints

### Category
- `GET /api/app/category`: List categories
- `GET /api/app/category/{id}`: Get category
- `POST /api/app/category`: Create category
- `PUT /api/app/category/{id}`: Update category
- `DELETE /api/app/category/{id}`: Delete category

### Allergen
- `GET /api/app/allergen`: List allergens
- `GET /api/app/allergen/{id}`: Get allergen
- `POST /api/app/allergen`: Create allergen
- `PUT /api/app/allergen/{id}`: Update allergen
- `DELETE /api/app/allergen/{id}`: Delete allergen

### Product
- `GET /api/app/product`: List products (admin)
- `GET /api/app/product/public-list`: List active products (public)
- `GET /api/app/product/{id}`: Get product
- `POST /api/app/product`: Create product
- `PUT /api/app/product/{id}`: Update product
- `DELETE /api/app/product/{id}`: Delete product

### Cart
- `GET /api/app/cart/my-cart`: Get current user's cart
- `POST /api/app/cart/add-to-cart`: Add item to cart
- `PUT /api/app/cart/{id}`: Update cart item quantity
- `DELETE /api/app/cart/{id}`: Remove item from cart
- `DELETE /api/app/cart/clear-cart`: Clear entire cart
- `GET /api/app/cart/cart-total`: Get cart total

### Order
- `POST /api/app/order`: Create order from cart
- `GET /api/app/order/{id}`: Get order details
- `GET /api/app/order`: Get all orders (SuperAdmin)
- `GET /api/app/order/my-orders`: Get current user's orders
- `PUT /api/app/order/{id}/mark-as-paid`: Mark order as paid (SuperAdmin)
- `PUT /api/app/order/{id}/cancel`: Cancel order

## Technical Implementation Details

### Domain Layer

All entities inherit from ABP base classes:
- `FullAuditedAggregateRoot<Guid>`: For entities with full audit support
- `CreationAuditedAggregateRoot<Guid>`: For entities with creation audit only
- `Entity`: For junction tables

### Application Services

Services use ABP's `CrudAppService` for standard CRUD operations and implement custom methods where needed.

Permission checks are enforced using:
- Constructor policy assignment for CRUD operations
- `CheckPolicyAsync()` method for custom operations

### EF Core Configuration

- Fluent API configuration in `EcommerceDbContextModelCreatingExtensions`
- Table names prefixed with "App"
- Proper indexes on foreign keys and frequently queried fields
- Decimal precision for money fields (18,2)

### Background Jobs

Background jobs are queued using `IBackgroundJobManager` and execute asynchronously.

### AutoMapper

Mappings configured in `EcommerceApplicationAutoMapperProfile` for automatic DTO to Entity conversion.

## Security Considerations

- All admin operations require proper permissions
- Stock validation prevents overselling
- Users can only access their own cart and orders
- Soft-delete implemented for categories and products
- Audit logging tracks all changes

## Performance Optimizations

- Eager loading with `Include()` to prevent N+1 queries

## Image Upload System

### Overview
The application includes a robust file upload system for managing images for Products, Categories, and Allergens.

### Features
- Secure file uploads with validation
- Support for multiple image formats (JPG, PNG, GIF, WebP)
- Maximum file size: 5MB
- Automatic file naming using GUIDs to prevent conflicts
- Organized folder structure per entity type
- Automatic image deletion when entities are deleted or updated

### Folder Structure
```
wwwroot/
  uploads/
    products/       # Product images
    categories/     # Category images (future use)
    allergens/      # Allergen icons
```

### API Endpoints

#### Upload Image
```
POST /api/app/images/upload
Content-Type: multipart/form-data

Parameters:
- file: The image file (required)
- entityType: Entity type - "products", "categories", or "allergens" (required)

Response:
{
  "imageUrl": "/uploads/products/guid.jpg",
  "fileName": "guid.jpg"
}
```

#### Delete Image
```
DELETE /api/app/images/delete?imageUrl={imageUrl}

Parameters:
- imageUrl: The URL of the image to delete (required)
```

### Implementation Details

#### Image Upload Service
- **Location**: `Masroof.Ecommerce.Application/Images/ImageUploadService.cs`
- **Interface**: `IImageUploadService`
- **Features**:
  - File type validation (.jpg, .jpeg, .png, .gif, .webp)
  - File size validation (max 5MB)
  - Automatic GUID-based file naming
  - Automatic folder creation
  - Safe file deletion

#### Application Service
- **Location**: `Masroof.Ecommerce.Application/Images/ImageAppService.cs`
- **Endpoint**: Exposed via `ImageController`
- **Authorization**: Requires authentication

#### Automatic Cleanup
Images are automatically deleted in the following scenarios:
1. When a Product is deleted (ProductAppService:146-157)
2. When an Allergen is deleted (AllergenAppService:52-63)
3. When a Product's image is updated (ProductAppService:108-114)
4. When an Allergen's icon is updated (AllergenAppService:37-50)

### Frontend Integration

#### TypeScript Example
```typescript
// Service method
uploadProductImage(file: File): Observable<ImageUploadResultDto> {
  const formData = new FormData();
  formData.append('file', file);
  formData.append('entityType', 'products');
  
  return this.http.post<ImageUploadResultDto>(
    '/api/app/images/upload',
    formData
  );
}

// Component usage
onImageSelected(event: any): void {
  const file = event.target.files[0];
  if (file) {
    this.imageService.uploadProductImage(file).subscribe(
      result => {
        this.product.imageUrl = result.imageUrl;
        console.log('Image uploaded:', result.imageUrl);
      },
      error => {
        console.error('Upload failed:', error);
      }
    );
  }
}
```

### Security Considerations
1. **File Type Validation**: Only allowed image formats can be uploaded
2. **File Size Limit**: Maximum 5MB to prevent abuse
3. **GUID Naming**: Original filenames are replaced to prevent path traversal attacks
4. **Separate Folders**: Images organized by entity type for better management
5. **Authentication Required**: Only authenticated users can upload/delete images

### Cloud Storage Migration
To migrate to cloud storage (e.g., Azure Blob Storage):

1. Install ABP Blob Storing package:
```bash
dotnet add package Volo.Abp.BlobStoring.Azure
```

2. Update `ImageUploadService` to use ABP's `IBlobContainer`:
```csharp
public class ImageUploadService : IImageUploadService
{
    private readonly IBlobContainer _blobContainer;
    
    public ImageUploadService(IBlobContainer blobContainer)
    {
        _blobContainer = blobContainer;
    }
    
    public async Task<string> UploadImageAsync(IFormFile file, string folder)
    {
        var blobName = $"{folder}/{Guid.NewGuid()}{Path.GetExtension(file.FileName)}";
        
        using (var stream = file.OpenReadStream())
        {
            await _blobContainer.SaveAsync(blobName, stream);
        }
        
        return blobName; // Return blob URL from your cloud provider
    }
}
```

3. Configure Azure Blob Storage in `appsettings.json`:
```json
{
  "AbpBlobStoring": {
    "Azure": {
      "ConnectionString": "your-connection-string",
      "ContainerName": "ecommerce-images"
    }
  }
}
```
